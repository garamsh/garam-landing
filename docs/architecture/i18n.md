# Internationalization

How the site is localized: which locales exist, how a visitor reaches one, and where the copy lives. The code is `src/features/i18n/` and `src/proxy.ts`.

## Current decisions

- The site has two locales, `en` (default) and `ko`. Each is served at its own path, `/en` and `/ko`.
- The locale code is the URL segment, the `<html lang>` value and the hreflang code. One entry per locale in `src/features/i18n/locales.ts` holds its language name, its Open Graph locale and its dictionary.
- All visible copy and the page title and description live in one typed dictionary per locale under `src/features/i18n/dictionaries/`. The `Dictionary` type is the contract: a locale missing a key fails the type check.
- `/` redirects to a locale path. `src/proxy.ts` reads `Accept-Language`, matches on the primary language subtag (`ko-KR` is `ko`), honours quality values, and falls back to `en`. The redirect response carries `Vary: Accept-Language`.
- The language switcher is plain links. It marks the current locale with `aria-current` and sets `lang` and `hrefLang` on each link.
- Unknown locale segments are not generated and answer 404.
- Facts that are not translated, such as the trade name and registration number, live in `src/lib/company.ts`; the dictionary holds only their labels.
- The feature imports no other feature. Other features reach it only through its `index.ts`.

## Rationale

- Two static locales do not need an i18n library. A typed dictionary module gives compile-time key parity, and a small matcher replaces `negotiator` plus `@formatjs/intl-localematcher` for one header.
- Locale in the path, with each locale a separate URL, is what Google's localized-versions guidance asks for, and it is the routing the Next.js internationalization guide describes for the App Router.
- Adding a locale is one dictionary file and one entry in `locales.ts`; the sitemap, hreflang set and static params follow from that entry.

## Open questions

- Hangul and Latin copy use different display faces; whether a third locale in another script needs its own override is unsettled until one is proposed.
